# Реквизиты дела — текущие, год — только в формах

23.11.2026. Задача 16 бэклога (часть задачи 3), просьба Романа 20.11 —
`intent/2026-11-20-fod-po-razdelam.md`. Схему предложил Роман 23.11 (вариант
«ФОД у раздела дела с флажком» он отклонил). Оценка: большая, две-три
сессии; меняется правило, в какое дело ложится запись, — ревьюер по
`REVIEW.md` обязателен. **Код — после «Делай».**

## 1. Как хочет Роман (его слова, 23.11)

«Из вкладки дело убрать год, год пусть будет только во вкладках рождение,
брак, смерть. Пользователь набирает ФОД, переходит в любой раздел,
устанавливает набираемый год и начинает индексацию. При смене раздела
(рождение, брак, смерть) или года пользователем ФОД не меняется, он
меняется только после того как пользователь сам руками его изменил.»

Ответы на вопросы (23.11):
1. Церковь, село, уезд, губерния, архив — так же, как ФОД: «да».
2. Правка ФОД у старой записи — в записи на правке, строкой «изменить»: «да».
3. Напоминание при смене года на форме — «оставить».
4. Папка сканов — не трогать: «по папке сканов у нас есть отдельная задача»
   (задача 3).

## 2. Что сейчас

- Реквизиты (архив, фонд, опись, дело, церковь, село, уезд, губерния) и год
  книги — у **дела года**, строка `mk_case`; запись ссылается на дело
  (`entry.case_id`); новую запись года `records::save_entry` кладёт в первое
  дело года (`case_for_year`). Экран «Дело» (`src/CaseHeader.tsx`) правит
  дело и заводит год («Сохранить дело», `records::save_case`).
- Смена года на форме (`src/newyear.ts`, `case_open_year`) заводит дело
  нового года копией прежнего и напоминает проверить ФОД.
- Импорт Familio и Excel-индексатора уже заводит **дело на каждые
  реквизиты** — у года бывает несколько дел (выбор на «Деле», п. 94).
- Выгрузки, слияние, поиск берут реквизиты записи из её дела.

## 3. Что делаем

**Модель.** Дело = год книги + реквизиты (как у импорта). Программа помнит
**текущие реквизиты** прихода — настройка прихода `case_reqs` (JSON: архив,
фонд, опись, дело, церковь, село, уезд, губерния, индексатор). Сохранение
новой записи берёт её год (как сейчас — год книги с формы) и текущие
реквизиты и кладёт запись в дело с **тем же годом и теми же реквизитами**
(сравнение по `trim`, пустое = пустое); такого нет — заводит его.
- Старые записи и дела **не трогаются**: ни одна из записей Романа не
  переносится и не пересохраняется. Схема базы не меняется.
- Текущие реквизиты при первом запуске новой версии — из дела последней
  записи (как сейчас «текущее дело»).
- Ключ прихода (`parish_key`, частоты «по приходу») и его перенос при смене
  церкви/села (`move_parish_stats`, п. 139) — как сейчас, от текущих
  реквизитов.

**Экран «Дело».** Поля реквизитов без года книги; «Сохранить» меняет только
**текущие реквизиты** — уже набранные записи не меняются (текст пояснения
под полями это говорит). Блок «Дела прихода» (вместо выбора года, п. 94):
список дел — год, реквизиты, число записей; у дела «Исправить реквизиты» —
правит это дело, то есть все его записи (массовая правка опечатки в ФОД).
Перед массовой правкой — вопрос «изменить у N записей?».

**Формы.** Год — только в формах (поле уже есть). Смена года руками
(`newyear.ts`) больше не заводит дело заранее — дело появится при
сохранении первой записи года. Напоминание остаётся одной жёлтой строкой,
набор не останавливает: «Новый год книги — реквизиты: Ф.56 Оп.6 Д.4,
Христорождественская. Другие? Измените на «Деле».» Смена раздела ничего не
меняет. «Продолжить с места» — как сейчас (год и страница последней записи).

**Запись на правке.** Над формой строка её реквизитов «Ф.56 Оп.6 Д.4,
Христорождественская, с. Борисоглебское — изменить». «Изменить» — те же поля,
что на «Деле»; при сохранении записи она ложится в дело своего года с новыми
реквизитами (найти или завести); старое дело, оставшееся без записей,
убирается (`case_delete_empty`). Текущие реквизиты прихода при этом не
меняются.

**Что не меняется.** Выгрузки Familio и Excel (берут реквизиты из дела
записи), слияние приходов, импорт, поиск, папка сканов (по году — задача 3),
память подсказок.

## 4. Что надо проверить при работе (риски)

- Всё, что сейчас опирается на «текущее дело» (`case_current`, `workYear` в
  `App.tsx`, `case_load`, дело для блока скана, «Сохранить дело» с годом без
  записей, «новый год с чистого листа»), — перечень собрать исследователем
  до кода; каждое место — в спеку решением.
- Две записи одного года с разными реквизитами — в «Набрано» видны вместе
  (список по году, а не по делу).
- Слияние: дела помощника с теми же годом и реквизитами — не дублировать
  без нужды (как сейчас).
- Правка записи меняет её дело — память поиска (`drop_search`/счётчик),
  частоты «по делу» (`usage_stat` scope `case`) — перенести, как при правке.

## 5. Проверки

- Тесты крейта: сохранение с текущими реквизитами — дело найдено/заведено;
  смена реквизитов — старые записи в прежнем деле; смена года — новое дело
  с теми же реквизитами; правка записи с «изменить» — запись в новом деле,
  пустое старое убрано; массовая правка дела — у всех его записей.
- `db/test_entry.py`, `db/test_upgrade.py` (старая база: текущие реквизиты из
  последней записи, записи и выгрузка не изменились).
- Выгрузка Familio/Excel на базе с двумя делами одного года — у записей свои
  ФОД; валидатор xlsx.
- e2e (Windows): реквизиты Д.4 → рождение; Д.6 → смерть того же года;
  выгрузка — разные ФОД; перезапуск — текущие реквизиты Д.6.
- Стенд: экран «Дело» без года; напоминание при новом годе; строка
  реквизитов у записи на правке; «Дела прихода» и массовая правка.
- `test_incidents.py`: «смена ФОД меняла его у всех записей года»
  (20.11.2026).

## 6. Порядок работы (на две-три сессии)

1. Исследователь: все места «текущего дела» и года дела → дополнить р. 4.
2. Крейт: текущие реквизиты, найти/завести дело при сохранении, правка
   записи с переносом, массовая правка дела — с тестами.
3. Окно: «Дело» без года, «Дела прихода», напоминание, строка у записи.
4. Проверки, стенд, e2e, агенты, отчёт.
