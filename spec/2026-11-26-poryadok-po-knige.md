# Спека: порядок «по вводу | по книге» в «Набрано» и в выгрузке

26.11.2026. Бэклог, задача 19, и долг р. 3 п. 30. Замысел —
`intent/2026-11-26-otvety-na-sborku-25-11.md` (замечание 5 Романа, пример
Олега; дополнение: «Сортируем по обряду»; замечание 6 Нинель).

## Как было

- «Набрано» (`entry_list`, `db/statements.sql`) — записи года книги
  `ORDER BY e.id DESC`: последняя набранная сверху.
- Выгрузки: Familio (`familio_birth/_marriage/_death`) — `ORDER BY
  e.book_year, e.id`; Excel (`x_row`, лист «МК») — номер строки `n` по тому
  же порядку. Пропущенная запись, набранная позже, встаёт после более
  поздних.
- Формы берут из списка «Набрано» последнюю набранную запись: `saved[0]`
  (месяц следующей записи, `monthOnYearChange`), счёт по полу
  (`nextCount(saved, …)`), страница из списка (`pageFromList`),
  предохранитель страницы (`pageOverflow`). Этот порядок им нужен «по
  вводу» при любом выборе.

## Что делаем

### 1. Переключатель

- В заголовке «Набрано» каждой формы, справа в строке «Набрано: 24 — за
  1905 год», — мелкая подпись «Порядок:» и сегментированный переключатель
  «по вводу | по книге»; выбранная кнопка залита основным цветом, как
  активная вкладка. По умолчанию — «по вводу».
- Выбор один на все разделы и все приходы: общая настройка
  `ui_entry_order` (`COMMON_SETTINGS` в `parish.rs`), «1» — по книге, иначе
  по вводу; помнится после перезапуска. Три формы слышат друг друга через
  событие окна (как замки, `src/flags.ts`).

### 2. Порядок «по книге»

Ключ записи:
1. **Дата обряда** (Роман 26.11.2026): год, месяц, день обряда
   (`rite_*`). В «Браках» обряд — венчание, оно хранится в полях события
   (`event_*`, `rite_*` пусты). Если дня обряда нет, а дата события
   полная, — дата события (обряд без даты, `Wait.byEvent`). Ни той, ни
   другой полной (год, месяц и день) — запись **без даты**.
2. **Страница** как номер листа: число и «об» — «5» < «5об» < «6»; у
   разворота «5об-6» — первая часть «5об». Страница без числа или пустая —
   считается меньше любой страницы с числом.
3. **Номер записи**: № м. или № ж. (что есть); при равных — мужская
   первой. Без номера — меньше любого номера.
4. Последний ключ — номер записи в базе (`id`): порядок всегда один.

Записи с датой упорядочены по ключу (1–4). Запись без даты встаёт сразу
после записи, у которой пара «страница, номер» наибольшая среди меньших,
чем у неё (сравниваются все записи списка, с датой и без); нет такой —
идёт первой. Несколько записей без даты за одной — по своей паре.

В «Набрано» последняя по книге — сверху (список показан в обратном
порядке). Новая запись сразу встаёт на своё место.

Порядок считает одна функция крейта `book_order::book_order` (на вход —
записи с полями даты, страницы, номеров, `id`; на выход — порядок `id`),
с тестом на примеры Романа. Разбор страницы — `page_key` там же. Копия —
в шиме стенда.

### 3. «Набрано»

- Команда `entry_list` отдаёт у каждой строки место в порядке книги
  (`book`, с нуля); окно при «по книге» показывает строки по нему —
  последнюю по книге первой (`shownOrder`, `src/entryorder.tsx`).
- Формы держат **два списка**: `saved` — по вводу, как сейчас (для
  месяца, счёта, страницы, предохранителя); показ — отдельный, в выбранном
  порядке. «Продолжить с места» (`last: true`) не меняется.
- В строке по-прежнему дата события (как сейчас): «по книге» идёт по дате
  обряда, поэтому даты в строках могут идти не подряд — это нормально.

### 4. Выгрузки

- Familio и Excel (и лист «МК») — в порядке, выбранном в «Набрано»;
  первой — самая ранняя (по вводу — первая набранная, по книге — первая по
  книге). Годы — как сейчас: по году книги.
- Как: перед `export_prepare` Rust заполняет временную таблицу
  `x_order(entry_id, pos)` по `book_order` (при «по вводу» она пуста);
  `x_entry` получает `pos`, все `ORDER BY e.book_year, e.id` в блоках
  выгрузки → `ORDER BY e.book_year, e.pos, e.id` (номер строки `n` — так
  же). Пустая `x_order` даёт прежний порядок.
- В окне выгрузки (`src/ExportPanel.tsx`) строка «Порядок записей: по
  книге» и тот же переключатель (та же настройка).
- Номера, даты и страницы записей не меняются ни в одном режиме.

### 5. Долг п. 30: «скан» под полосой прокрутки (Нинель, Mac)

Полоса прокрутки macOS лежит поверх правого столбца списка. Отступ справа
у последней ячейки строки (`.facts.saved td:last-child`), не у списка:
цвет строк остаётся на всю ширину (п. 11). На Windows полоса своё место
занимает сама — отступ там лишь чуть шире.

## Как проверить

- Тест крейта `book_order`:
  - № м. 3 (15.01, стр. 5), № м. 5 (17.01, стр. 6), затем № м. 4 (16.01,
    стр. 5об) → 3, 4, 5;
  - одинаковая дата и страница — по номеру, мужская № 4 раньше женской
    № 4;
  - запись без даты стр. 5об-6 № м. 8 → сразу после стр. 5об-6 № м. 7;
    без даты и меньше всех → первая;
  - «5» < «5об» < «5об-6» (= «5об») < «6»; «10» > «9»;
  - брак — по дате венчания; рождение без дня обряда — по дате события.
- Тест выгрузки (`db/test_export.py` или тест крейта): «по книге» —
  Familio 3, 4, 5; «по вводу» — как раньше (3, 5, 4).
- Стенд: переключатель в «Набрано» трёх разделов, выбор помнится после
  перезагрузки, новая запись встаёт на место; месяц и счёт новой записи —
  от последней набранной, а не от верхней строки; строка порядка в окне
  выгрузки; «скан» в правом столбце виден при прокрутке.

## Что не меняется

Схема базы (настройка — строка `setting`), импорт, слияние, номера и даты
записей, «продолжить с места».
